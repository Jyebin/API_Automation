1. [WebView] 대시보드 API — tests/view/dashboard.spec.ts

❌ 학습 현황 요약 조회 (v1) & 유효하지 않은 파라미터 케이스 — 각 1건
테스트 방법유효한 JWT를 Authorization 헤더에 담아 GET /api/v1/view/dashboard/study 호출. 두 번째 케이스는 무관한 파라미터 { invalid_param: 'xyz' }를 추가 전송하여 서버가 무시해야 함을 검증.
기대 응답200 OK — 학습 현황 데이터 반환
실제 응답500 Internal Server Error
실패 원인서버 내부 오류 서버 측 예외 처리 누락. 테스트 계정(raontestqa1)에 학습 이력 데이터가 없거나, v1 엔드포인트 내부 코드에서 NULL 데이터를 처리하지 못해 500이 발생하는 것으로 추정. v2 엔드포인트(/api/v2/view/dashboard/study)는 동일 계정으로 200 반환 — v1만 영향 받음.
권장 조치서버 팀에 GET /api/v1/view/dashboard/study 500 에러 로그 확인 요청. 학습 이력 없는 계정에 대한 NULL safety 처리 필요.
❌ 실습 캘린더 조회 (4건) — v1 기본, 연월 파라미터, 과거 날짜, 마이페이지
테스트 방법 유효한 JWT로 아래 4개 엔드포인트를 각각 호출:
  • GET /api/v1/view/dashboard/calendar — 파라미터 없음
  • GET /api/v1/view/dashboard/calendar?year=2025&month=01 — 특정 연월
  • GET /api/v1/view/dashboard/calendar?year=2020&month=01 — 과거 날짜
  • GET /api/v1/view/dashboard/calendar/my — 마이페이지 캘린더
기대 응답200 OK — 캘린더 일정 데이터 반환 (수업 없으면 빈 배열)
실제 응답422 Unprocessable Entity
실패 원인비즈니스 규칙 제약 테스트 계정(raontestqa1)이 현재 어떤 수업에도 수강 등록되어 있지 않음. 캘린더 API가 수강 등록 이력을 필수 전제 조건으로 요구하는 것으로 보임. 수강 이력 없는 계정에 대해 200 + 빈 배열을 반환하는 것이 올바른 동작이나, 현재 422 처리하고 있어 개선 여지 있음.
권장 조치테스트 계정에 실습 수업 수강 등록 처리 또는, 수강 이력 없는 계정에 대해 200 + 빈 배열을 반환하도록 서버 측 수정 요청.
❌ 실습 캘린더 조회 (v2) — 1건
테스트 방법유효한 JWT로 GET /api/v2/view/dashboard/calendar 호출
기대 응답200 OK
실제 응답422 Unprocessable Entity
실패 원인비즈니스 규칙 제약 v1과 동일. v2에서도 수강 등록 이력 필수.

2. [회원] 내 프로필 API — tests/member/profile.spec.ts

❌ 타인 프로필 조회 — 자기 자신 user_id 조회 — 1건
테스트 방법먼저 GET /api/v1/member/my/profile로 자신의 userid를 획득한 뒤, 해당 userid를 GET /api/v1/member/others/profile?user_id={userid}에 전달하여 자기 자신을 타인 프로필 API로 조회.
기대 응답200 OK — 자신의 공개 프로필 정보 반환 (또는 400 자기자신 조회 불가 오류)
실제 응답422 Unprocessable Entity
실패 원인비즈니스 규칙 제약 서버가 타인 프로필 API로 자기 자신 조회를 허용하지 않음. 이는 설계 상 의도된 제한일 수 있음. 다만 오류 코드가 422인데, 명확한 비즈니스 규칙 거부라면 400 Bad Request가 더 적절한 코드임. 테스트 계정으로는 이 시나리오를 정상 통과시키기 어려움 (자신의 ID만 알고 있음).
권장 조치타인 ID로 조회할 수 있는 별도 테스트 계정 추가 또는 서버 팀에 자기 자신 조회 시 422 대신 400 + 명확한 오류 메시지 반환 요청.

# 엔드포인트 예상 동작 실제 응답 영향 범위
